# Regressor / Oracle Metric-Selection Experiments

This directory holds the ClustOpt search-map configs for the **dynamic
metric-selection** experiment phase. The goal is to compare clustering search
driven by *dynamically selected* CVI metrics against fixed CVI baselines, for
every dataset view (`x_only`, `y_only`, `xy_2d`).

> **No true-K leakage.** None of these configs use the ground-truth cluster
> count. Every K-based algorithm searches `n_clusters` / `n_components` in
> `[2, 3, 4, 5]`. The selected K is meant to be *measured* against the true K
> afterwards, never fed into the search.

## CVI modes

### `regressor_dynamic`

Resolves the metric weights from a trained MLP utility regressor **before** the
search runs, per dataset record/view:

1. Load the regressor artifacts from `model_run_dir` (config, feature/target
   columns, head mapping, per-fold checkpoints + scalers).
2. Predict the per-metric utility vector from the record/view feature vector.
   * `checkpoint_policy: fold_ensemble` averages all folds (`folds/fold_*/best_model.pt`).
   * `checkpoint_policy: best_single_fold` uses a single `fold_index` (default 0).
3. Select the **Top-K** metrics by predicted utility.
4. Convert utilities to weights (`softmax` with `softmax_temperature`, or
   `normalized_positive`).
5. Strip the `utility__` prefix and hand the `{metric: weight}` dict to the
   ordinary generic CVI evaluator.

```jsonc
"cvi": {
  "type": "regressor_dynamic",
  "params": {
    "model_run_dir": "results_analysis/mlp/combined",
    "checkpoint_policy": "fold_ensemble",
    "top_k": 5,
    "weighting": "softmax",
    "softmax_temperature": 0.5,
    "metric_name_prefix": "utility__",
    "feature_source": "features/features_records.csv",
    "view_aware": true,
    "fallback_on_error": true,
    "fallback_metrics": { "silhouette": 1.0 }
  },
  "params_generic": { "remove_noise": true, "noise_label": -1, "min_clusters": 2 }
}
```

> **`model_run_dir`** points at the trained run `results_analysis/mlp/combined`
> (resolved relative to the repo root). Swap it out — and regenerate via
> `generate_experiment_configs.py` — to target a different trained regressor.

### `oracle_dynamic`

Same selection/weighting machinery, but it reads the **true** utility vector
instead of predicting it. It is an *upper bound* for comparison and must never
be used for real inference. No oracle configs are shipped here (the experiment
runner will construct them), but the resolver is fully implemented:

```jsonc
"cvi": {
  "type": "oracle_dynamic",
  "params": {
    "top_k": 5,
    "weighting": "softmax",
    "softmax_temperature": 0.5,
    "metric_name_prefix": "utility__",
    "utility_source": "utility/<view_id>/utility_vector.json",
    "view_aware": true,
    "fallback_on_error": true,
    "fallback_metrics": { "silhouette": 1.0 }
  }
}
```

### Baselines (`generic`)

Fixed CVI weight sets, unchanged generic behaviour:

| Folder | Metrics |

| `silhouette_single` | `silhouette` |

## Top-K and softmax temperature

| Folder | `top_k` | `softmax_temperature` |
| --- | --- | --- |
| `regressor_top1_softmax_t05`  | 1  | 0.5 |
| `regressor_top3_softmax_t05`  | 3  | 0.5 |
| `regressor_top5_softmax_t05`  | 5  | 0.5 |
| `regressor_top10_softmax_t05` | 10 | 0.5 |

Lower temperature ⇒ sharper weighting toward the highest-utility metric;
`0.5` keeps Top-1 dominant while still mixing in the rest of the Top-K.

## Optuna budget

Every config uses Optuna:

```jsonc
"search_algorithm": { "type": "optuna", "params": { "n_trials": 50, "timeout": 150, "patience": 15 } }
```

The current `OptunaSearch` accepts `n_trials`, `timeout`, and `patience`; the
direction is fixed to `maximize` and the sampler defaults to TPE, so
`direction` / `sampler` / `seed` from the original spec are intentionally
omitted to stay compatible with the implementation.

## Dimension-specific search spaces

* **x_only / y_only** — `kmeans`, `minibatch_kmeans`, `gmm`, `agglomerative`,
  `birch`, `dbscan`, `hdbscan`, `hdbscan_constrained-2/3/4/5`, `optics`.
  `spectral` is excluded from 1-D to reduce runtime. `y_only` uses slightly
  wider density ranges (eps, `min_cluster_size`, birch threshold).
* **xy_2d** — all of the above **plus `spectral`**, with broader 2-D ranges.

`meanshift` is intentionally excluded from every view (too slow and not needed
for these experiments).

`hdbscan_constrained-N` fixes `n_components` to `N` (the persistence-bin count
is part of the algorithm identity, not a K search).

## Runner integration (how weights get resolved)

The dynamic evaluator is constructed by `ClusteringOptimizationBuilder` like any
other CVI, but resolves its weights lazily. The experiment runner should call
`resolve(...)` once per dataset/view before the search:

```python
evaluator = builder.build_evaluator()              # RegressorDynamicCVIEvaluator
evaluator.resolve(feature_vector=feat)             # preloaded, or:
evaluator.resolve(dataset_dir=ds_dir, view_id="x_only")  # on-demand file read
# ... then run the search; evaluator behaves like a generic CVI.
```

Preloaded `feature_vector` (regressor) / `utility_vector` (oracle) avoid file
I/O. If neither preloaded values nor `dataset_dir`+`view_id` are available and
resolution fails, the evaluator falls back to `fallback_metrics` (when
`fallback_on_error` is true) or raises.
